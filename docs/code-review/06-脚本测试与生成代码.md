这些文件不是请求路径上的库代码。它们仍会进入仓库，其中的密钥和绝对路径会变成真实风险。审查没有改这些文件。

## 仓库里的明文字符串密钥

下列测试把 DashScope 密钥写成 Python 字符串，并赋给 `DASHSCOPE_API_KEY`：

| 文件 | 大约行号 |
| --- | --- |
| `backend/test_dashscope_direct.py` | 8 |
| `backend/test_dashscope_v2.py` | 8 |
| `backend/test_dashscope_live_min.py` | 36 |

密钥形态是 `sk-` 后接 32 位十六进制。文档不复制完整值。这三份文件若曾提交或同步到其他机器，应在 DashScope 控制台作废该密钥，再从历史中移除。测试改为只读环境变量，缺密钥时跳过而不是写死（V-09）。

`backend/test_config.py` 会打印密钥前 10 位。本地调试可以理解，不应在 CI 日志里出现。

`providers/base.py` 与 `config.py` 注释中的 `sk-xxx` 是占位符，不是可用密钥。

## 前端生成代码

`frontend/src/services/generated/` 由 openapi-typescript-codegen 生成，文件头写着 do not edit。结构：

| 目录 | 内容 |
| --- | --- |
| `core/OpenAPI.ts` | `BASE` 初始 `''`，实际由 `generatedClient.ts` 覆盖；`TOKEN` 为空 |
| `core/request.ts` | 组装 URL、查询和 body。支持 Basic 用户名密码，本项目没有启用 |
| `core/BaseHttpRequest.ts` / `AxiosHttpRequest.ts` | HTTP 实现 |
| `services/*.ts` | `AicssService`、`ProjectsService`、`ScriptMotionService`、`V2ComposeService`、`ModelsService`、`LayersService`、`V23DMeshExportService`、`Settings` 相关服务 |
| `models/*.ts` 与 `schemas/*.ts` | 与 FastAPI Pydantic 模型对应的类型 |

`frontend/.schema-check-tmp/` 是另一次生成的副本，容易和 `src/services/generated` 漂移。它不应被应用 import。若打包配置用了宽泛的 `include`，要确认没有打进产物。

生成客户端没有认证参数。后端加上鉴权之后，必须重新生成，并在 `generatedClient.ts` 设置 `TOKEN`，而不是手改 `generated/` 里的文件。

`OpenAPI.ts` 里 `WITH_CREDENTIALS` 为 false，`CREDENTIALS` 却是 `'include'`。当前 `WITH_CREDENTIALS` 为 false 时不会带 cookie。以后若打开凭证，又与后端 `allow_origins=["*"]` 冲突：浏览器会拒绝“任意源 + 凭证”。改认证方式时这两处要一起设计。

## OpenAPI 与工作流 JSON

`frontend/openapi.json` 是生成客户端的输入。后端路由改了而不更新这个文件，前端类型会继续编译通过、运行时 404 或丢字段。

`workflows/*.json`（`lama_inpaint.json`、`depth_anything_v2.json`、`txt2img_basic.json`）是 ComfyUI 图。本仓库的 FastAPI 路径不直接执行它们。若其中含密钥或本机绝对路径，不应提交。本次未把工作流节点当作服务端漏洞。

## 文档与代码的偏差

`docs/ARCHITECTURE_DECISIONS_mesh_export.md`、`docs/EXECUTION_TASKS.md`、`docs/PROJECT_STATUS.md` 描述的是设计意图。以本次读到的代码为准的差异：

| 文档或注释中的意图 | 代码现状 |
| --- | --- |
| 设置接口会掩码密钥 | GET 会掩码；POST 不拒绝掩码；磁盘与 localStorage 仍是明文 |
| 项目路径安全 | 产物文件名有正则；`project_id` 与 `shotId` 在创建、删除、合成上没有统一沙箱 |
| Blender 可用即能渲染 | `check_blender_available` 只探测可执行文件 |
| 记录接口的路径检查 | `script_record.resolve_rel` 有沙箱，其他存储类没有复用 |

以代码为准改行为时，应回写这些设计文档，避免下一轮实现按旧文档把沙箱删掉。
