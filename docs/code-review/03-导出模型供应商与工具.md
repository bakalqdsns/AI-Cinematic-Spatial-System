仍有两个路径问题：

1. `output_file = out_dir / f"{scene.scene_id}.{ext}"`（1276）。`scene_id` 含 `..` 时，Blender 的输出参数指向临时目录之外。

## `llama_server_manager.py`（344 行）

| 符号 | 行 | 值或行为 |
| --- | --- | --- |
| `BACKEND_DIR` | 34 | `Path(__file__).parent.parent.parent.resolve()`，即 `backend/` |
| `find_available_model` | 79 | 在 `backend/llmserver` 找 GGUF |
| `start_server` | 129 | `Popen` 列表参数 |
| 启动命令 | 176–184 | `-m <gguf> -c 8192 -ngl 99 --host 0.0.0.0 --port <DEFAULT_PORT> --alias qwen2.5-7b-q4_k_m` |
| `stop_server` | 244 | `subprocess.run([STOP_SCRIPT])` |
| `ensure_server_running` | 334 | `main.lifespan` 在 `model_mode=="local"` 时调用 |
| `_auto_unload_loop` | 294 | 空闲后卸模型 |

`--host 0.0.0.0` 使 llama.cpp 的 OpenAI 兼容接口在所有网卡上监听，且该进程没有 API 密钥。局域网客户端可以绕过 FastAPI，直接对 8080 发对话（V-07）。`--alias` 与 `local_llm` 的默认模型名 `qwen2.5-7b-q4_k_m` 必须一致，否则 `/v1/chat/completions` 找不到模型。这是跨文件约定，写在 `08` 索引。

`stop_server` 执行仓库里的批处理。批处理若可被工作区写入覆盖，停服务就变成执行攻击者脚本。当前脚本在 `backend/llmserver/`，不在项目工作区，风险取决于该目录的写权限。

`creationflags` 在 Windows 上是 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`。进程脱离后，uvicorn 崩溃不一定带走 llama-server，可能留下占着 8080 和显存的孤儿进程。

### `providers/dashscope.py`（261 行）

`DashScopeProvider`：`chat`（54）、`vlm_analyze`（93）、`generate_image`（132）、`generate_video`（173）、`_download_video`（246）。与 `dashscope_client.py`、`video_adapter.DashScopeFilmProvider` 三处都实现了 DashScope 调用。密钥字段都指向 `dashscope_*_api_key`，但请求体和错误处理会分叉。改官方 API 时要三处一起改（I-05）。

### `providers/openai_compatible.py`（313 行）

`OpenAICompatibleProvider`：`_headers`（52）放 `Authorization` 和 `extra_headers`。`chat`（80）、`vlm_analyze`（120）、`generate_image`（159）、`generate_video`（199）、`_download_video`（298）。

`extra_headers` 来自设置里的 provider dict。匿名调用方可以让服务器向任意 `base_url` 附加任意头。若头里再放内网服务的凭据，就成了带凭据的 SSRF。即使不放凭据，也是开放的服务器端请求（V-05、V-06）。

| 函数 | 行 | 调用方 |

| `estimate_depth_from_bbox` | 135 | 粗深度 |

`load_image_from_url_or_base64` 第 53–61 行：以 `http` 开头就 `httpx.Client.get`，跟随重定向，无主机限制，无响应大小限制。`http://127.0.0.1`、云元数据地址、内网文件服务都会被服务器代为访问（V-06）。`file:` 不走这条分支，而走 base64 解码，通常只会 400。

`base64.b64decode` 没有最大长度。一张声明为图像的超大字符串会在解码时占满内存（V-14）。

`Image.open` 使用 Pillow 默认的像素上限（约 1.78 亿像素）。对这台 16GB 显存、32GB 内存的机器，默认值仍然允许先在 CPU 上分配很大的数组。应在本模块入口把 `Image.MAX_IMAGE_PIXELS` 降到业务需要的上限，并在 `httpx` 响应上限制字节数。

### `utils/temporal_tracker.py`（621 行）

`TemporalTracker`（219）：`extract_features`（249）、`match_objects`（360）、`track_sequence`（421）、`compute_scene_links`（591）。

`endpoints_sequence.py` 第 194 行有另一套同名类，字段名 `BoundingBox`、`CrossFrameObject`、`SceneLink` 也重复。序列接口目前用的是端点文件里的类，工具模块可能只被测试或部分服务引用。合并前要先用引用搜索确认调用点，避免删掉仍在用的那一份（I-04）。

`compute_iou`（108）与端点内 `_bbox_iou` 的边界条件（零面积框）可能不同，追踪 ID 会因此不稳定。

### `utils/vlm_utils.py`（227 行）

`_vlm_chat`（14）→ 云或本地 VLM。`classify_scene`（26）、`detect_objects`（58）、`parse_detection_result`（103）、`vlm_detect`（142）、`get_fallback_prompt`（137）。

`parse_detection_result` 从模型文本抽框。解析失败时返回空列表而不是 4xx，调用方会把“没检测到”和“模型胡言”显示成同一种空结果。

### `utils/gpu_concurrency.py`（38 行）

`_MAX_CONCURRENT_GPU_JOBS = 2`。`get_gpu_sem()`（28）返回进程内信号量。只有显式 `async with get_gpu_sem()` 的路径受限制。`endpoints.py` 的分析与修复、`auto_three_view` 的角色生成、Blender 导出不共享这一把锁，所以全局并发不是 2（V-13）。

### `utils/__init__.py` 与 `services/__init__.py`、`models/__init__.py`

包初始化。`models/__init__.py` 导出 `model_manager`。其他业务不要在 `__init__` 里再加载权重，否则 import 端点模块就会占 GPU。当前加载在各 loader 的 `load()`，这一点是对的。
