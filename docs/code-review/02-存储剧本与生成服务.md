本文件覆盖 `backend/app/services/` 里负责磁盘布局、剧本、镜头、图像和视频的模块。模型加载、网格导出和供应商在 `03`。

`save_object_archive`（179）把 RGBA 和 JSON 写到对象目录。`make_object_rgba`（130）、`bbox_of_mask`（166）是纯数组运算。`rgba_to_data_uri`（123）会把整张图放进响应，大图时内存和响应体一起涨。

## `layer_exporter.py`（482 行）与 `ground_reconstructor.py`（345 行）

`export_layers`（235）按深度阈值切前景、中景、背景、天空。`compute_sky_mask`（94）、`inpaint_occluded_layers`（329）调用修复。`export_layers_to_data_uris`（407）与 `export_layers_to_disk`（439）是两种出口。`build_z_offset_table`（467）的数值要和前端 `Viewer3D.tsx` 的 `LAYER_THICKNESS` 一致，否则纸模厚度对不上。

`ground_reconstructor.py`：`default_intrinsics`（63）、`backproject`（81）、`ransac_fit_plane`（146）、`reconstruct_ground`（218）。内参来自 `endpoints_layers._parse_intrinsics`。异常内参（零焦距）会在除法处抛错，端点应返回 400 而不是 500。

## `occlusion_holes.py`（208 行）

`compute_occlusion_holes`（96）用对象 mask 与深度比较。`merge_hole_masks`（183）给修复接口。`holes_to_dicts`（197）是 HTTP 响应形状。纯计算，风险在输入图的解码成本。

## `download_jobs.py`（220 行）与 `download_progress.py`（130 行）

`DownloadJobs.start`（115）按模型名启动后台任务。`DownloadJob.update_progress`（71）被 `download_progress.report_file_progress`（34）调用。进度存在进程内存，多 worker 时状态不一致。

`make_tqdm_callback`（60）包 Hugging Face 的 tqdm。回调里的模型名来自固定枚举时是安全的；若 `model_name` 路径参数未限制在已知集合，下载函数可能把任意仓库 ID 交给 `snapshot_download`（见 `endpoints_models.download_model` 与各 loader 的 `_snapshot_download_hf`）。应对照 `download_model` 的允许列表。当前实现若只接受 `depth`、`sam2` 等固定名字，则仓库 ID 不可由请求指定，风险降为“匿名触发已知大文件下载”。
## `script_record` 与 `ProjectStore` 的双写

同一个 `WORKSPACE_DIR / <project_id>` 上有两套清单：`manifest.json`（`ProjectStore`）和 `projects.json`（`script_record`）。前端记录服务写后者，分析管线写前者。删除项目只走 `delete_project` 时会把两者一起递归删掉；只调用记录接口不会删 manifest。恢复和迁移要同时看两个文件（I-03）。
