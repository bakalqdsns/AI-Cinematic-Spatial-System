# 漏洞与改进方案

编号在其他审查文档里被直接引用。级别沿用 `00-审查总览.md`。每条都给出位置、原因、会造成什么、建议改法。本次没有改代码，下面的改法是方案，不是已落地的补丁。

改进时先做 P0，再做 P1。P0 不完成时，后面的路径校验会被同一批未认证调用方绕过用途，但路径校验本身仍然要做，因为认证失败或绑定地址配错时它们是第二层。

## V-01 严重：服务无认证且监听所有网卡

**位置**

- `backend/app/config.py`：`host = "0.0.0.0"`，`port = 8000`，`reload = True`
- `backend/app/main.py` 第 217–223 行：CORS `allow_origins=["*"]`，方法与头同样为 `*`
- 全部 router 没有 `Depends` 鉴权
- `frontend/src/services/generated/core/OpenAPI.ts`：`TOKEN` 为空

**原因**

任何能访问该端口的客户端都可以调用删除项目、改设置、启停 llama-server、下载模型、合成视频。浏览器里的其他网站也能发起这些请求：简单 GET 可以被任意源读取；带 JSON 的 POST 会先预检，而 `Access-Control-Allow-Origin: *` 会让预检通过。

`allow_credentials=True` 与 `allow_origins=["*"]` 同时出现时，浏览器对“带凭证”的请求会直接失败。当前前端 `WITH_CREDENTIALS` 为 false，不带凭证，所以星号源仍然放行读响应。

**会造成什么**

用户打开恶意网页，或局域网里另一台机器访问 `http://<本机>:8000`，就可以删掉 `.workspace/projects` 下的项目、换成攻击者的云端密钥、把 `llm_base_url` 指到外部、拉起占满显存的模型下载。

**改法**

1. 默认 `host=127.0.0.1`。需要局域网时用显式环境变量打开，并同时要求令牌。
2. 增加共享密钥：启动时若 `AICSS_API_TOKEN` 为空则拒绝绑定非回环地址。校验放在一个依赖里，挂到除 `/health` 以外的路由。`/health` 只返回 `{"status":"ok"}`。
3. CORS 改为前端源列表，例如 `http://localhost:5173`。不要使用 `*`。
4. `reload` 默认改为 `False`。
5. 前端 `generatedClient` 在请求头带该令牌。令牌放环境变量，不要写进仓库。

## V-02 严重：`project_id` 未规范化导致目录逃逸

**位置**

- `ProjectStore._project_dir`，`project_store.py` 第 519 行：`return self._workspace_dir / project_id`
- `delete_project`，同文件第 690–696 行：`shutil.rmtree(proj_dir)`
- `endpoints_projects.delete_project`，第 240–245 行：删除前没有 `_validate_safe(project_id)`
- `video_composer.compose_clips` 第 446 行：`workspace_dir / "projects" / pid / "compose"`
- `get_composed_video`、`get_rendered_video`：只检查 `filename`，不检查 `project_id`
- `project_store_mesh._project_dir` 同样直接拼接

**原因**

FastAPI 的路径参数可以是 `..`。`Path` 拼接后，`is_dir()` 对父目录为真，`rmtree` 会删除工作区的父目录。合成接口用同一个 ID 创建输出目录，`mkdir(parents=True)` 会在工作区外建目录并写 mp4。

`script_record.project_dir` 拒绝 `..`、斜杠和反斜杠，说明作者知道要防，但这函数没有被 `ProjectStore` 使用。

**会造成什么**

`DELETE /api/aicss/projects/..` 可能删除 `backend/.workspace` 甚至更上层，取决于工作区的实际父目录和进程权限。合成接口可以把文件写到工作区外。

**改法**

新增一个函数，例如放在 `script_record.py` 旁并改名为双方共用的 `safe_project_dir(project_id)`：

1. 拒绝空字符串、`.`、`..`、任何斜杠、反斜杠、空字符。
2. 用与 `_validate_safe` 相同的字符集，或复用 `slugify`。
3. `resolved = (root / project_id).resolve()`，再要求 `resolved` 等于根目录的子路径：`root.resolve() in resolved.parents`。
4. `delete_project`、`read_manifest`、`compose_clips`、两个 `FileResponse`、mesh 存储全部改走这个函数。
5. 补测试：`..`、`foo/bar`、`foo\\bar`、超长 ID、Windows 保留名 `CON`。

## V-03 严重：创建项目时 `shotId` 进入目录名

**位置**

`project_store.py` 的 `create`，第 558–563 行：

```text
project_id = f"{ts}_{shot_id}"
proj_dir.mkdir(parents=True, exist_ok=True)
```

调用方是 `endpoints_projects.create_project`（91）和 `create_project_json`（134）。两者只对 `shotId` 做 `strip`。

**原因**

同文件的 `slugify`（84）已经能去掉路径字符，`create` 没有调用它。`shotId` 为 `x/../../outside` 时，`mkdir(parents=True)` 按操作系统语义创建到工作区外。

**会造成什么**

匿名上传一张图即可在任意可写路径建目录并写入 `input/original.png` 和 `manifest.json`。

**改法**

`project_id = f"{ts}_{slugify(shot_id)}"`。`slugify` 结果再过一遍 V-02 的 `resolve` 检查。拒绝 slug 为空的情况（`slugify` 会落到 `unnamed`，可以接受）。

`save_step` 的文件名（第 612 行 `step_dir / name`）同样要经过 `_validate_safe`，不能只在 HTTP 层碰运气。

## V-04 高：ffmpeg 与下载接口读取任意本机路径

**位置**

- `endpoints_compose.api_compose`：`clipPaths`、`audioTracks[].path`、`colorGrade.lut_path`
- `video_composer.apply_transition` 第 166–172 行：concat 文件内容为 `file '{path}'`，命令含 `-safe 0`
- `apply_color_grade`：LUT 路径进入 `-vf`
- `compose_clips` 第 457 行：只要 `Path(clip).exists()` 就交给 ffmpeg
- `get_media_file`：允许工作区与 `CACHE_DIR` 下的任意文件
- `download_shot_archive` 第 296 行：`glob(f"*_{shot_id}_archive.zip")`，并把 `build_shot_archive` 返回的路径直接 `FileResponse`
- `refine_from_render`：`glob(f"*{shot_id}*.mp4")`，输出名使用 `shot_id`

**原因**

ffmpeg 参数是列表，没有 shell 注入，但输入文件没有限制在项目目录。`-safe 0` 允许 concat 列表指向任何路径。路径中的单引号会截断 `file '...'` 这一行。LUT 路径里的滤镜特殊字符会改变 `-vf`。

`get_media_file` 的根目录检查是对的，范围仍然是整个工作区和整个 Hugging Face 缓存。

**会造成什么**

调用方可以让服务器用 ffmpeg 读取 `~/.aicss/settings.json`（若先复制或路径可被 ffmpeg 打开）、SSH 密钥、其他项目成片，或把输出写到 `project_id` 逃逸后的位置。glob 中的 `*` 会匹配到同一目录里别的镜头包。

**改法**

1. 请求只收相对路径。`resolve` 后必须落在 `safe_project_dir(project_id)` 之内，且后缀在 `{.mp4,.mov,.webm,.wav,.mp3,.aac,.cube}` 内。
2. concat 列表不要用引号拼接。对每条路径使用 ffmpeg concat 的转义规则（反斜杠和单引号），或改为滤镜 `concat`，不写列表文件。
3. 去掉 `-safe 0`，或仅在确认所有路径与列表文件同目录后再使用。
4. LUT 只允许项目内 `.cube`，滤镜参数用 ffmpeg 的路径转义，不把原始字符串拼进 `-vf`。
5. `FileResponse` 前再次 `resolve` 并检查父目录。
6. `shot_id` 与 `filename` 使用 `_validate_safe`，glob 改为精确文件名。

## V-05 高：匿名修改运行时设置与上游地址

**位置**

- `endpoints_settings.post_settings`（80）
- `settings_manager.RUNTIME_FIELDS` 含 `llm_base_url`、各 `api_key`、`providers`
- `settings_manager.update_settings`（216）调用 `LLMObserver` 与 `cloud_router.invalidate_cache`
- `DELETE /api/aicss/settings/store` 清空 `~/.aicss/settings.json`
- `providers` 元素中的 `base_url`、`api_key`、`extra_headers`

**原因**

设置接口与业务接口共享“无认证”。攻击者把 LLM 或图像供应商的 `base_url` 改成自己的服务器后，下一次用户操作会把剧本和提示词发过去。`extra_headers` 会让后端在那个请求上附加攻击者指定的头。

**会造成什么**

提示词与画面外泄；用户的后续生成计费到攻击者的账户或相反，攻击者把密钥换成自己的再从配额获利；删除设置文件让本机密钥从磁盘消失（内存里可能还在，重启后丢失）。

**改法**

1. 并入 V-01 的令牌。
2. `base_url` 做解析：只允许 `https`，禁止回环、链路本地、元数据地址和内网网段，除非显式配置 `AICSS_ALLOW_PRIVATE_UPSTREAM=1`（仅本机 llama-server 需要）。
3. 清空设置要求单独确认字段，例如 `{"confirm":"reset"}`，避免浏览器预检通过后的直接 DELETE。
4. 日志只打字段名，不打 `providers` 的值。`update_settings` 第 251 行目前只打键名，保持这样。

## V-06 高：服务端按用户提供的 URL 取图

**位置**

| 函数 | 文件 | 行 | 客户端 |
| --- | --- | --- | --- |
| `load_image_from_url_or_base64` | `utils/image_utils.py` | 39 | `httpx`，跟随重定向 |
| `_load_image` | `endpoints.py` | 431 | 上面的函数 |
| `_load_mask` | `utils/paper_diorama.py` | 29 | `requests.get` |
| `_fetch_url` | `character_generator.py` | 418 | `urllib.request.urlopen` |
| `_fetch_url` | `scene_generator.py` | 361 | 同上 |
| `_download_video` | `video_adapter.py`、两个 provider | 多处 | 供应商返回的 URL |

**原因**

以 `http` 开头即下载，无主机白名单、无响应字节上限、无重定向次数限制。`urllib.request.urlopen` 还接受 `file:`。角色与场景那两处 URL 来自云端响应：供应商被攻破、或 V-05 把供应商指到攻击者时，响应里的 URL 决定服务器去访问哪里。

**会造成什么**

访问 `http://127.0.0.1:8080`、本机管理端口、云元数据地址。大响应拖垮内存。`file:///C:/Users/.../settings.json` 在 `urlopen` 那条路径上可以读本地文件。

**改法**

做一个 `fetch_public_http(url, max_bytes)`：

1. 只允许 `https`（本机开发可另开允许的主机列表）。
2. 解析 DNS 后拒绝私网、回环、链路本地、云元数据。重定向每一跳都重新检查。
3. 流式读取，超过例如 20MB 即断开。
4. `image_utils`、`paper_diorama`、两个 `_fetch_url`、视频下载全部改用它。
5. 图像接口优先只接受 data URL。远程 URL 若保留，必须走上面的函数。

## V-07 高：llama-server 监听所有网卡且无密钥

**位置**

`llama_server_manager.py` 第 176–184 行：`--host 0.0.0.0 --port` 默认端口，`--alias qwen2.5-7b-q4_k_m`。`endpoints_llm.llm_start` 匿名可调用。`main.lifespan` 在本地模式会自动启动。

**原因**

该进程不经过 FastAPI。即使给 FastAPI 加了令牌，8080 仍然开放。别名与 `useSettingsStore` 默认的 `llm_model`、`configure_llm` 使用的模型名是跨文件约定，改一处就会让对话 404，但不能靠改别名来代替认证。

**会造成什么**

局域网直接调用本地模型，占满 GPU，也可作为免费的开放模型接口。

**改法**

`--host 127.0.0.1`。若 llama.cpp 版本支持 API key，加上并只放在后端环境变量，由 `LocalLLMClient` 发送。`llm_start` / `llm_stop` 纳入 V-01 的令牌。

## V-08 高：密钥明文落盘，且掩码可以被写回

**位置**

- `settings_store.py` 第 13–16 行说明：密钥原样写入 `~/.aicss/settings.json`。Windows 上没有收紧 ACL。
- `settings_manager.get_settings` 把密钥显示为 `***`，`update_settings` 不把 `***` 当作“保持原值”。
- `useSettingsStore.ts` 第 99–104、216 行：`localStorage['aicss_runtime_settings_v1']` 保存 patch，包含密钥。

**原因**

掩码只发生在 GET 的响应副本上。磁盘、浏览器存储、测试脚本是另外三条明文通道。任何把 GET 正文再 POST 回去的客户端都会把真密钥换成星号。前端当前的 `saveSettings` 只发 patch，降低了误伤概率，没有消除后端行为。

**会造成什么**

本机其他用户、备份软件、XSS、恶意扩展都能读到云端密钥。错误的保存会让生成突然全部 401，排障时看起来像供应商故障。

**改法**

1. 密钥不进 `settings.json` 的可提交字段。使用环境变量或操作系统凭据存储。若必须写文件，Windows 上设置仅当前用户可读的 ACL，文件权限失败则拒绝保存。
2. `update_settings`：值为 `***`、空字符串或缺失时不覆盖已有密钥。另提供显式 `clear_api_key: true`。
3. `persistToLocalStorage` 删除键名以 `_api_key` 结尾的字段，以及 `providers[].api_key`。
4. 轮换已经写进浏览器的密钥：发版说明里要求用户清 localStorage 并在云端作废旧密钥。

## V-09 高：测试文件中的可用密钥

**位置**

`backend/test_dashscope_direct.py`、`backend/test_dashscope_v2.py`、`backend/test_dashscope_live_min.py`。详见 `06` 文档，此处不复写密钥。

**改法**

立刻在 DashScope 控制台作废该密钥。测试改为 `os.environ["DASHSCOPE_API_KEY"]`，没有则 `pytest.skip`。用历史清理工具从 git 对象里去掉该字符串。之后加一条 CI，拒绝匹配 `sk-[0-9a-f]{32}` 的提交。

## V-10 中：浏览器 localStorage 保存密钥

与 V-08 是同一数据的前端副本。单独列出是因为即使后端改成只进环境变量，现有前端仍会在保存时写入 localStorage。改 `persistToLocalStorage` 即可，不必等凭据存储做完。

## V-11 中：上传与 JSON 没有体积上限

**位置**

- `endpoints_projects.create_project`：`await image.read()` 无限制
- `endpoints_record.upload_project_file` 与 `ingest_action_video`：整文件读入内存
- `write_record`：任意大小的 `projects.json`
- `image_utils.base64_to_pil`：不限制 base64 长度
- Pillow 默认 `MAX_IMAGE_PIXELS`

**会造成什么**

一个请求占满内存或磁盘。解压炸弹在解码阶段放大。

**改法**

反向代理或 FastAPI 限制 body，例如图片 25MB、视频 200MB、JSON 2MB。分块写入磁盘，不要 `await file.read()` 进内存。在 `image_utils` 顶部设置更小的 `Image.MAX_IMAGE_PIXELS`，并捕获 `DecompressionBombError` 返回 400。记录上传限制扩展名，与 `_MEDIA_SUFFIXES` 对齐。

## V-12 中：错误响应与健康检查泄露本机信息

**位置**

- `main.health`：`llm_base_url`、模型状态
- `main.health_models`：权重绝对路径，异常文本截断 500 字后返回
- `get_settings_store`：`settings.json` 的绝对路径，含用户名
- `api_compose` 第 133 行：`RuntimeError` 原文回给客户端，ffmpeg stderr 可能含路径
- `download_shot_archive` 第 307 行：`detail=f"Archive failed: {e}"`

**改法**

对外只返回稳定错误码（`CLIP_MISSING`、`PROJECT_NOT_FOUND`）。路径和 stderr 进 `aicss.log`。`/health` 在未认证时只返回状态与版本。

## V-13 中：缺少全局资源配额

**位置**

`gpu_concurrency.py` 的信号量上限为 2，但分析、修复、三视图、Blender、模型下载不全部使用它。`auto_*` 用 `create_task` 在后台跑云端请求。`export_scene` 的超时随对象数增长，仍然很长。

**会造成什么**

匿名并发把 16GB 显存打满，进程被 CUDA 杀掉。云端模式则持续产生费用。`faulthandler` 能留下崩溃栈，不能阻止请求进来。

**改法**

所有 GPU 入口共用 `get_gpu_sem()`，包括 Blender 与本地出图。云端调用按项目或令牌做简单计数，超过则 429。模型下载同时只允许一个任务，`download_jobs` 已有单模型状态，应拒绝并行的第二个大文件。后台 `kickoff_after_parse` 要有取消和最大队列长度。

## V-14 中：记录上传可覆盖项目内任意相对路径

**位置**

`script_record.write_bytes`（143）配合 `upload_project_file`。`safe_rel` 挡住了 `..`，没有挡住 `projects.json`、`manifest.json` 或其他扩展名。

**会造成什么**

同一项目的清单被覆盖，后续读取把攻击者的 JSON 当成剧本记录。不能逃出项目目录，所以级别低于 V-02。

**改法**

上传只允许 `_MEDIA_SUFFIXES` 加上明确的 `.json` 清单接口。清单只走 `put_project_record`，并给 `projects.json` 定 schema，拒绝未知的巨大嵌套。

## V-15 中：剧本内容直接影响 LLM 与后续文件名

**位置**

`script_parser.parse_script` → `_llm_chat_safe` → `shot_generator` / `slugify`。

**原因**

这是产品功能：剧本就是提示词。没有隔离系统提示与用户剧本的结构保证时，模型输出的角色名会变成目录名。`slugify` 降低了路径风险，不降低“模型按剧本指示调用更多云端生成”的费用风险。

**改法**

系统提示与用户正文分消息角色发送（若已经分开，保持）。对一次解析产生的角色数、镜头数、自动三视图任务数设上限。自动 `kickoff_after_parse` 改为前端确认后再排队。

## 逻辑与结构改进（不是单独的入侵路径）

### I-01 锁的创建不是原子的

`ProjectStore._get_lock`（528）和 mesh 存储里类似的字典。两个协程可能拿到两把锁。改成 `asyncio.Lock` 保护字典本身，或 `setdefault`。CPython 的字节码切换点比想象中多，不要依赖“单线程所以没事”。

### I-02 `_normalize_time` 定义了两次

`script_parser.py` 第 1338 行与第 1648 行。删掉或改名其中一个，并给两种时间格式各写一条测试。

### I-03 一个项目两套清单

`manifest.json` 与 `projects.json`。在 `00` 的数据流里写清谁是权威。删除、迁移、缺失文件检查要读同一份，或在一份里引用另一份的哈希。

### I-04 两套 `TemporalTracker`

`utils/temporal_tracker.py` 与 `endpoints_sequence.py` 第 194 行。合成一个类，序列端点只做 HTTP。

### I-05 DashScope 三套客户端

`dashscope_client.py`、`providers/dashscope.py`、`video_adapter.DashScopeFilmProvider`。保留 provider 那一套，另外两套改为调用它。

### I-06 `endpoints_compose.py` 带 BOM

文件以 U+FEFF 开头，`ast.parse` 失败。用编辑器另存为 UTF-8 无 BOM。不影响当前 CPython 导入，但会破坏静态检查。

### I-07 灯光与纸模参数三份副本

`lighting/presets.ts`、`presets/lighting/*.json`、`mesh_exporter` 里的 `make_paper_material` 与 `paper_material.py`。以 JSON 预设为源，前端和 Blender 都读它。`ENERGY_SCALE`（`Viewer3D.tsx` 第 104 行）要么写进预设，要么删掉魔法数。
