# 前端手写代码

范围是 `frontend/src` 里除 `services/generated/` 以外的文件。生成客户端只在 `06` 说明。HTTP 基址统一来自 `generatedClient.ts` 的 `DEFAULT_BACKEND`：`import.meta.env.VITE_AICSS_BACKEND || 'http://localhost:8000'`。`vite.config.ts` 没有配置 dev proxy，浏览器直接访问后端，因此后端 CORS 对开发环境是必需的，同时也把接口暴露给任意网页（见 V-01）。

没有发现 `dangerouslySetInnerHTML` 或 `eval`。密钥问题来自 `localStorage` 和把密钥 POST 到无认证后端。

## 状态

### `store/useSettingsStore.ts`（236 行）

| 符号 | 行 | 行为 |
| --- | --- | --- |
| `STORAGE_KEY` | 10 | `aicss_runtime_settings_v1` |
| `loadFromLocalStorage` | 88 | `JSON.parse` 后并进默认设置 |
| `persistToLocalStorage` | 99 | 把 patch 整包写入 localStorage |
| `fetchSettings` | 122 | GET 设置；密钥为 `***` 时保留本地值 |
| `saveSettings` | 183 | POST patch，再把 patch 写入 localStorage |
| `fetchModelDownloads` | 163 | 直接 `fetch` 到 `/api/aicss/models/status`，不走 generated client |

`saveSettings` 第 216 行注释写明要把 API 密钥留到下一会话。`localStorage` 任何同源脚本都能读，密钥与 `llm_base_url` 一起落盘（V-10）。

合并逻辑只在前端避免把 `***` 再显示成密钥。后端 `update_settings` 仍会接受字面量 `***`。本 store 的 `saveSettings` 只发送 patch，正常点击保存不会回写掩码。若 `setLocalField` 先把掩码放进状态、再被某个“保存全部”路径送出，密钥会被毁掉。保存路径应在前端丢掉掩码，后端也应拒绝掩码占位符。

`fetchModelDownloads` 另行拼接 URL，和 `DEFAULT_BACKEND` 重复。改环境变量时两处都要改。

### `store/useScriptStore.ts`（1153 行）

剧本、角色、场景、运动、批进度的主 store。动作调用 `services/scriptService.ts`。体量大，解析、三视图、场景资产、运动生成的加载状态都在这里。一个失败的 `set` 容易覆盖另一条流水线的 `error`。

建议按“剧本 / 角色资产 / 场景资产 / 运动”拆 store，而不是继续加字段。这是结构改进，不单独立漏洞编号。

### `store/useAppStore.ts`（800 行）

当前镜头、原图、深度、分割、图层、纸模参数。调用 `aicssService.ts`。图像以 data URL 留在内存，长会话会把多张 1080p 以上的 PNG 留在 JS 堆里。可把大图只留 IndexedDB 的 id，内存里放缩略图。

### `store/useSequenceStore.ts`（202 行）

序列分析结果，对应 `sequenceService.ts` 与 `/v2/sequences`。`sequence_id` 从响应写入后再用于 GET。后端若把序列放在进程内存，刷新页面后 id 仍在、数据已没，前端应把 404 显示成“请重新分析”，而不是通用失败。

### `store/useShotWorkflowStore.ts`（62 行）

镜头步骤的 UI 阶段，字段少，无独立网络调用。

### `store/useTimelineStore.ts`（234 行）

| 符号 | 行 | 作用 |
| --- | --- | --- |
| `ShotClip` | 29 | 时间线上的片段 |
| `nextClipId` / `nextAudioId` | 93 / 99 | 本地 id |
| `defaultClipPath` | 105 | 由镜头推出片段路径 |
| `useTimelineStore` | 113 | 片段、音轨、转场、调色 |

`defaultClipPath` 产生的路径会进入 `composeService` 的 `clipPaths`。若这里拼出工作区外路径，后端会照单全收（V-04 的前端一侧）。路径应使用项目内相对路径，由后端解析。

## 服务

### `services/generatedClient.ts`（22 行）

`generatedClient` 与 `DEFAULT_BACKEND`。`OpenAPI.TOKEN` 保持 `undefined`，请求不带认证头。

### `services/settingsService.ts`（137 行）

`RuntimeSettings` 含 `dashscope_*_api_key`、`toapi_llm_api_key`、`providers`。`fetchSettings` / `updateSettings` 对应 GET/POST `/api/aicss/settings`。类型把密钥标成 `string | null`，掩码 `***` 也是合法字符串，类型系统区分不了“未返回”和“占位符”。

全部把 data URL 放在 `imageUrl`。大图以 base64 膨胀约 4/3 后经浏览器发给本机后端。

### `services/scriptService.ts`（707 行）

封装解析、角色、镜头、三视图、场景资产、运动、相机路径。函数与 `endpoints_script.py` 的路由一一对应，字段在这里做 camelCase 与 snake_case 转换。转换漏字段时，后端用默认值继续生成，前端却以为已经提交。建议为每条请求加运行时校验（zod 或生成的 schema），不要只靠手写映射。

### `services/sequenceService.ts`（109 行）

`analyze`、`getSequence`、`getSceneLinks`。对应 `endpoints_sequence.py`。

### `services/recordService.ts`（209 行）

上传 `projects.json` 和文件，`rel` 由调用方传入。应在这里拒绝以 `..` 开头或含反斜杠的 `rel`，即使后端 `safe_rel` 已经拒绝。双重检查可以让错误出现在保存按钮旁，而不是 400 正文。

### `services/composeService.ts`（179 行）

提交 `clipPaths`、音轨、LUT，再去拉合成后的 mp4。类型 `AudioTrack`、`ColorGrade`、`TransitionKind` 被 `useTimelineStore` 重新导出。

### `services/meshExportService.ts`（195 行）

对象、图层、整场导出，以及下载 GLB。下载 URL 含 `project_id` 与 `mesh_id`。

### `services/projectFiles.ts`（22 行）

把项目文件 URL 拼出来，供 `<img>` / `<video>`。查询参数里的 `rel` 需要 `encodeURIComponent`。漏编码时，文件名里的 `#` 或 `?` 会截断请求。

### `services/promptCheck.tsx`（121 行）

`checkCharacterPrompt`（44）、`checkScenePrompt`（64）、`checkActionPrompt`（78）、`checkV2vPrompt`（96）、`buildV2vPrompt`（105）、`PromptIssueList`（114）。规则应与 `prompt_contract.py` 保持同一份。现在是手工复制。

## 工具

### `utils/db.ts`（123 行）

IndexedDB 库 `aicss-sessions`，版本 1，对象仓库 `sessions`。

| 函数 | 行 |
| --- | --- |
| `openDB` | 29 |
| `saveSession` / `updateSession` / `loadSession` / `listSessions` / `deleteSession` | 47 / 58 / 77 / 87 / 102 |
| `blobToUrl` / `dataUrlToBlob` | 112 / 116 |

会话里有原图和中间图，无加密。与 localStorage 的密钥分开存放，但都在同一浏览器配置文件里。公共电脑上的“记住密钥”和“记住剧本图”都会留下。

`blobToUrl` 使用 `URL.createObjectURL`。调用方不用时要 `revokeObjectURL`，否则长时间编辑会泄漏 blob URL。需要在删除会话的路径上成对释放。

### `utils/inpaintMask.ts`（260 行）

画笔生成 mask data URL，交给 `inpaintImage`。坐标换算要和 `ImageCanvas` 的显示尺寸一致，否则修复区域偏移。这是正确性问题。

### `utils/depthUtils.ts`（129 行）与 `utils/depthSplit.ts`（127 行）

深度着色与分层阈值。阈值默认值要和 `layer_exporter` 的分层边界一致，否则屏幕上的四层和后端导出的四层不是同一套像素。

### `utils/cameraAnimation.ts`（225 行）

`CameraKeyframe` 与插值。播放用在 `CameraPathPlayer.tsx`。字段对应 `CameraKeyframeDTO`。

### `utils/resolution.ts`（68 行）

把 UI 分辨率转成后端 `size` 字符串。没有上限时，用户能请求远超显存的宽高。上限应与 `image_generator._round_to_multiple` 之前的拒绝条件相同。

### `lighting/presets.ts`（130 行）

Three.js 用的灯光预设。与 `backend/blender/.../presets/lighting/*.json` 和 `add_lighting.py` 是三份数据。界面预览亮度和 Cycles 成片会不一致（I-07）。

### `Viewer3D.tsx` 中的资源

`textureCache`（37）按 URL 缓存 `THREE.Texture`。`disposeCache`（50）要在项目切换时调用。不调用会保留上一项目的贴图，也会在下载新 GLB 前继续显示旧画面。`getOrLoadTexture`（39）对失败 URL 没有负面缓存，坏链会反复请求。

`PaperDioramaLighting`（70）与 `PresetLight`（108）用 `ENERGY_SCALE`。这个系数只存在于前端，Blender 预设不知道它。

## 前端侧改进顺序

1. 密钥只留在后端进程内存或系统凭据存储。`persistToLocalStorage` 跳过所有 `api_key` 字段。
2. 时间线与合成只传项目内相对路径。
3. `fetchModelDownloads` 改走 `DEFAULT_BACKEND` 或 generated client。
4. 把 `promptCheck.tsx` 视为后端 `prompt_contract.py` 的镜像，改规则时两处同时改，或删掉其中一处。
5. 拆分 `ScriptEditor.tsx` 与 `useScriptStore.ts`，按流水线而不是按文件行数。
